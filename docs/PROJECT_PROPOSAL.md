**对本次初审意见的回应（重点）**

初审指出上一版虽说明了离线抄读价值、核心由 MoonBit 承担，但目标停留在
"DL/T 645-2007 帧层与读数据应用层子集"，未满足本轮"协议实现须以完整标准
符合性为目标"的要求，单帧抄读案例不足以建立完整交互语义。本次已据此重构：

- **目标改为完整标准符合性**：实现标准第 7 章全部十二项功能码（08H 广播校时、
  11H~1BH 读/写/冻结/改速率/改密码/三类清零），而非仅读数据子集。
- **补齐完整交互语义**：三种应答控制码（正常 9x / 有后续 Bx / 异常 Dx）、
  读后续数据 0x12 的帧序号机制（1~255，请求应答序号一致）、异常错误信息字。
- **提供会话级完整案例**：读地址 → 读数据（有后续帧）→ 读后续数据（序号匹配）
  → 异常应答，逐字节报文与 CS 复算见 `docs/STANDARD_CONFORMANCE.md` 第 3.5 节。
- 上一条初审指出的报文语义错误（双字节长度、0x01 读命令、0xC1 错误应答）
  已在上一轮全部更正，本轮保持：经核对标准，评委意见成立，更正对照如下：

| 项目 | 更正前（错误） | 更正后（符合 645-2007） |
|---|---|---|
| 长度字段 | 双字节小端 | **单字节 L，帧长 12+L** |
| 读数据 | 0x01 | **0x11** |
| 读数据正常应答 | 0x81 | **0x91** |
| 读数据异常应答 | 0xC1 | **0xD1**（D7+D6 同时置位） |
| 数据域 | 未编码 | **逐字节 +33H / -33H** |
| 功能码 | 0x01~0x0F 连续 | **08H、11H~1BH 离散定义** |
| DI | 正向总电能 00000000 | **00010000**，传输序 DI0..DI3 |

**标准符合性目标与关键报文语义**

- 目标：以 **DL/T 645-2007 完整标准符合性（协议层）**为目标，覆盖数据链路层帧格式与
  应用层全部十二项功能码及完整交互语义，服务离线抄表开发、抓包分析与协议
  一致性静态检查。设备能力差异（DI 支持、倍率、权限、串口参数）需实物确认，

**标准时效性核查（截至 2026-11-25）**

- 全国标准信息公共服务平台与国家数字标准馆均标注 DL/T 645-2007 为**现行**版本，
  全部代替 DL/T 645-1997，未列出新的 DL/T 645-202x 替代版；本项目的版本引用有效。
- DL/T 698.45-2017 与 DL/T 698.45—2026 是面向对象的数据交换协议（2017 版废止
  日期 2026-12-26，2026 版同日实施），代替关系是 698.45-2026 → 698.45-2017，
  与 DL/T 645-2007 无关，不能作为"645 已被替代"的依据。
- 公开标准文本的备案注释涉及特定事件/费率/阶梯数据项，不改帧格式、控制码与
  十二项功能码；DI 元数据目录与物理层电气参数边界见符合性文档第 0/1.2 节。
- 关键语义：单字节长度 L；控制码 D7 方向 / D6 异常 / D5 后续帧 / D4~D0 功能码；
  应答控制码正常 9x / 有后续 Bx / 异常 Dx；读后续数据帧序号匹配；数据域逐字节
  +33H；数据标识 DI3DI2DI1DI0 低字节在前传输；BCD 数值按 DI 小数位与单位解析。
- **会话级完整案例**（读地址 → 读数据含后续帧 → 读后续数据序号匹配 → 异常应答，
  逐字节报文与 CS 复算）见 `docs/STANDARD_CONFORMANCE.md` 第 3.5 节；单帧
  1234.56 kWh 案例见第 3 节。全部报文由黄金测试逐字节锁定，可用 `moon test`
  与 `moon run cmd/roundtrip` 复现。

**项目简介**

moonmeter 是 MoonBit 生态中首个实现中国电能表通信规约 DL/T 645-2007 的
协议栈，以完整标准符合性（协议层）为目标。它提供符合标准的帧编解码（68H 起始、
BCD 地址域、单字节长度、+33H 数据域、累加和校验、16H 结束）、标准全部
十二项功能码的请求构造与应答语义、多帧后续数据传输、BCD 电量读数编解码、
数据标识（DI）目录、电表模拟器、错误应答解码与规约一致性校验器，并以
库 + CLI + 可运行示例三层交付。
项目面向需要接入智能电表、充电桩计费与抄表系统的开发者，把"构造标准请求 →
模拟标准应答 → 解码读数 → 格式化 → 一致性校验"的完整抄读闭环搬到纯 MoonBit
代码中，无需硬件即可开发与验证。

**三个完整的使用场景**

1. **无硬件抄表开发**：上层系统在开发/CI 中用 `MeterSim` 注册读数并模拟电表
   标准应答，验证请求构造与读数解析逻辑，摆脱硬件在环依赖。调用链：
   `build_read_request`(0x11) → `MeterSim::answer_read`(0x91) → `decode_frame`
   → `parse_reading` → `decode_energy` → `format_energy`。示例输出 1234.56 kWh。
2. **规约一致性静态检查**：设备厂商把协议分析仪抓取的字节流喂给 CLI `validate`
   或库 `validate_stream`，自动定位坏校验、错误结束符、非法 BCD、短应答、
   未定义功能码、杂散字节等问题，并汇总错误/警告数，用作出厂静态筛查与回归测试。
   判定范围限于字节流可客观验证的格式与语义规则（见符合性文档 1.2 节）。
3. **充电桩 / 计费数据解析**：把电表上报的 BCD 电量寄存器按 DI 语义标注名称、
   单位与小数位并定点格式化，直接得到可展示、可对账的读数
   （如 "Forward active total energy = 1234.56 kWh"）。

**已实现的核心功能**

- ✅ 符合 DL/T 645-2007 的帧编解码：起始符、6 字节 BCD 地址、控制码、单字节长度、
  +33H 数据域编码、累加和校验（CS）与结束符；
- ✅ 标准全部十二项功能码（08H 广播校时、11H~1BH）的请求构造器，覆盖读数据/
  读后续/读地址/写地址/写数据/冻结/改速率/改密码/三类清零；
- ✅ 控制码表按标准离散定义，方向/异常/后续帧位语义正确；三种应答控制码
  （正常 9x / 有后续 Bx / 异常 Dx）可计算，`parse` 显示完整交互状态；
- ✅ 多帧交互：读后续数据 0x12 帧序号（1~255）构造、解析与一致性校验，
  `NextReading` 结构与 `sequence_matches` API；
- ✅ BCD 编解码（低字节在前），覆盖地址与电量；12 位地址合法性校验与互转；
- ✅ 数据标识（DI3DI2DI1DI0）目录：正向有功总/尖/峰/平/谷电能、电压、电流、
  功率，附标准名称、单位与小数位；
- ✅ 读数据请求（0x11）、正常应答（0x91）、异常应答（0xD1）构造与结构化解码；
- ✅ 电表模拟器（MeterSim）：注册任意读数并按标准应答读数据请求，可生成合规帧流
  或带错误（坏校验/坏结束符）的帧流；
- ✅ 规约一致性校验器：切帧并报告 stray_byte / bad_checksum / bad_end /
  truncated_frame / short_read_reply / unknown_function 等结构化诊断，
  一步到位 `validate_stream` API 与错误/警告计数；
- ✅ 电量定点格式化：`format_energy` 将 BCD 原始值按小数位格式化为 "1234.56"；
- ✅ CLI 五个子命令：parse / validate / read / commands / simulate；其中 `commands`
  现场打印全部功能码与三种应答控制码，`parse` 显示应答交互状态；
- ✅ 可运行闭环示例 `moon run cmd/roundtrip`；
- ✅ 61 项单元测试（含十二功能码、多帧序号、会话级报文的逐字节黄金测试及校验器边界回归）、
  三平台 CI、README、mooncakes 包文档；
- ✅ 标准符合性文档 `docs/STANDARD_CONFORMANCE.md`，含单帧与会话级完整案例。

**与现有工具的关系（复用 / 扩展 / 差异）**

- **生态空白**：经 mooncakes.io 检索确认，DL/T 645 / DL/T 698.45 / DLMS/COSEM
  电能计量规约在 MoonBit 生态中均无实现；邻近的 Modbus 协议栈与电表数据审计
  不涉及 645 帧格式，定位不同。
- **复用**：帧格式、控制码与数据标识遵循公开标准 DL/T 645-2007，可被上层抄表、
  计费、充电桩系统作为协议层复用。
- **扩展**：在帧编解码之上新增模拟器、错误解码、一致性校验与电量格式化，形成
  "编码-传输-解码-校验-展示"闭环。
- **差异**：moonmeter 回答"一段字节流是否符合 DL/T 645-2007 的格式与关键语义、
  读数是什么、有无可判定的规约违规"，提供可离线复现的验证与分析能力。
