# moonmeter 标准符合性说明与完整报文案例

本文档回应初审意见，明确三件事：**(1) moonmeter 的标准符合性目标与边界；
(2) 关键报文语义的准确定义；(3) 从标准请求帧、电表应答帧到读数输出的
逐字节完整案例。** 所有字节值均以 DL/T 645-2007《多功能电能表通信协议》
的帧格式、控制码定义与数据标识编码表为依据，并可用仓库代码复现。

---

## 1. 标准符合性目标与边界

### 1.1 目标

moonmeter 实现的是 **DL/T 645-2007 的帧层 + 读数据应用层子集**，面向
"离线抄表开发、抓包分析、协议一致性静态检查"三类场景。具体覆盖：

| 层次 | 覆盖内容 | 依据 |
|---|---|---|
| 帧结构 | 68H 起始、6 字节 BCD 地址（低字节在前）、单字节长度 L、数据域、CS 累加和、16H 结束 | 标准第 7 节帧格式 |
| 数据域编码 | 发送逐字节 +33H、接收逐字节 -33H | 标准"数据域传输加 33H"规则 |
| 控制码 | 传输方向 D7、异常标志 D6、后续帧 D5、功能码 D4~D0 | 标准控制码定义表 |
| 读数据应用 | 读数据请求/正常应答/异常应答、数据标识 DI3DI2DI1DI0、BCD 数值与小数位 | 标准附录 A 数据标识编码表 |

moonmeter 是**库 + CLI + 可运行示例**，可以作为协议层被上层抄表/计费系统
复用，也可以单独做离线分析与教学。

### 1.2 明确的边界（不夸大）

如实说明能力边界，避免误导：

- **本项目以"格式/语义正确"为目标，不声称"已通过真实设备互通认证"。**
  `MeterSim` 是按标准构造帧的软件电表，用于让上层逻辑在没有硬件时也能
  开发与回归；它不能替代真实电表的互操作测试。
- `validate_stream` 提供的是**静态一致性检查**：判定帧结构、CS、BCD 合法性、
  控制码是否为标准定义的功能码、应答数据域长度是否与语义相符等**可由字节流
  客观判定的规则**。它可以回答"这段报文是否违反标准的硬性格式规则"。
- 它**不**代替以下工作需要的内容：设备是否支持某个 DI、倍率与符号约定、
  认证/写权限、波特率与 8E1 串口参数、真实响应延时、厂商扩展（如拉合闸
  0x1C）。这些必须对照所用型号电表的通信手册并在实物上验证。
- 标准文本为公开行业标准；本项目为原创实现，未复制任何第三方源代码。

换言之，本项目支撑的是"**报文是否符合标准格式与关键语义**"的判断，
这正是离线抓包分析能客观给出的结论；"真实设备互通"属于硬件在环测试范畴，
不在本项目声明范围内。

## 2. 关键报文语义的准确定义

### 2.1 帧格式（单字节长度）

```
68  A0 A1 A2 A3 A4 A5  68  C  L  DATA[L]  CS  16
 │       6 字节地址        │  │  │    数据域   │  │
起始符                    起始 控制 长度      校验 结束
```

- **L 是单字节**，取值 0~200（读）/0~50（写），等于数据域字节数。无前导字节
  时整帧长度 = `12 + L`。
- **CS** = 从第一个 68H 起到数据域最后一个字节的算术和，取模 256（低 8 位），
  按**已加 33H 的实际发送字节**计算。
- 报文前可有 0~4 个 FEH 前导字节唤醒接收方，不计入帧长、不参与 CS。

### 2.2 控制码 C 的位定义

```
D7       D6        D5        D4 D3 D2 D1 D0
方向     应答标志   后续帧     功能码
0 主站命令  0 正常应答  0 无后续帧
1 从站应答  1 异常应答  1 有后续帧
```

功能码（D4~D0）是**离散定义**，不是 0x01~0x0F 顺序编号：

| 功能码 | 含义 | 功能码 | 含义 |
|---|---|---|---|
| 08H | 广播校时 | 15H | 写通信地址 |
| 11H | 读数据 | 16H | 冻结命令 |
| 12H | 读后续数据 | 17H | 更改通信速率 |
| 13H | 读通信地址 | 18H | 修改密码 |
| 14H | 写数据 | 19H~1BH | 需量清零 / 电表清零 / 事件清零 |

由此得到三种关键控制码：

| 场景 | 控制码 | 二进制 | 说明 |
|---|---|---|---|
| 主站读数据请求 | **0x11** | 0001_0001 | D7=0 主站，功能码 11H |
| 从站读数据正常应答 | **0x91** | 1001_0001 | D7=1 应答，D6=0 正常 |
| 从站读数据异常应答 | **0xD1** | 1101_0001 | D7=1 应答，D6=1 异常 |

> 澄清：`0x01` **不是** DL/T 645-2007 的读数据控制码（它是 1997 版或
> 其他协议的写法）；`0xC1` 的低 5 位为 01H，**不是**标准定义的读数据
> 功能码，因此也不是标准异常应答。本项目已按 2007 版更正为 0x11 / 0x91 / 0xD1。

异常应答的数据域首字节为**错误信息码**（同样经 +33H 传输）；本项目将其
解码为结构化 `ErrorCode`，未知取值保留为 `Unknown` 而不臆测。

### 2.3 数据标识 DI 与传输顺序

数据标识写作 **DI3 DI2 DI1 DI0**（四字节），**传输时低字节在前**，即
DI0 → DI1 → DI2 → DI3，再逐字节 +33H。以"当前正向有功总电能"为例：

```
标准书写          DI3 DI2 DI1 DI0 = 00 01 00 00
数据域传输顺序     DI0 DI1 DI2 DI3 = 00 00 01 00
加 33H 后           33 33 34 33
```

常用 DI：

| DI3DI2DI1DI0 | 数据项 | 数据格式 | 单位 | 小数位 |
|---|---|---|---|---|
| 00010000 | 当前正向有功总电能 | xxxxxx.xx | kWh | 2 |
| 00010100~00010400 | 正向有功 尖/峰/平/谷 | xxxxxx.xx | kWh | 2 |
| 02010100 | A 相电压 | xxx.x | V | 1 |
| 02020100 | A 相电流 | xx.xxx | A | 3 |
| 02030000 | 瞬时总有功功率 | xx.xx | kW | 2 |

数值按**压缩 BCD、低字节在前**编码，**不是二进制整数**。例如 BCD `56 34 12 00`
还原为 `123456`，按 2 位小数得到 `1234.56 kWh`。

## 3. 完整案例：标准请求 → 应答 → 读数输出

以下为统一地址 `123456789012`、读取"当前正向有功总电能"的完整案例。
地址 12 位十进制按每两位一个 BCD 字节、低字节在前编码为
`12 90 78 56 34 12`。省略 FE 前导字节。所有字节为十六进制。

### 3.1 主站请求帧

```
68 12 90 78 56 34 12 68 11 04 33 33 34 33 68 16
```

| 偏移 | 字节 | 字段 | 含义 |
|---|---|---|---|
| 0 | 68 | 起始符 | 帧起始 |
| 1~6 | 12 90 78 56 34 12 | 地址域 | 表号 123456789012，低字节在前 |
| 7 | 68 | 起始符 | 第二个起始符 |
| 8 | 11 | 控制码 | 主站读数据请求 |
| 9 | 04 | 长度 L | 数据域 4 字节 |
| 10~13 | 33 33 34 33 | 数据域 | DI 00010000 经 +33H：00 00 01 00 → 33 33 34 33 |
| 14 | 68 | CS | 字节 0~13 之和 0x368 的低 8 位 |
| 15 | 16 | 结束符 | 帧结束 |

CS 校验：`sum(68 12 90 78 56 34 12 68 11 04 33 33 34 33) = 0x368 → 0x68`。

### 3.2 电表正常应答帧

设电表该寄存器读数为 `1234.56 kWh`。BCD 值（低字节在前）为
`56 34 12 00`，+33H 后为 `89 67 45 33`。

```
68 12 90 78 56 34 12 68 91 08 33 33 34 33 89 67 45 33 54 16
```

| 偏移 | 字节 | 字段 | 含义 |
|---|---|---|---|
| 0 | 68 | 起始符 | 帧起始 |
| 1~6 | 12 90 78 56 34 12 | 地址域 | 应答回显实际通信地址 |
| 7 | 68 | 起始符 | 第二个起始符 |
| 8 | 91 | 控制码 | 从站读数据正常应答（D7=1, D6=0） |
| 9 | 08 | 长度 L | 8 字节 = 4 字节 DI + 4 字节值 |
| 10~13 | 33 33 34 33 | DI | 回显 00010000（+33H） |
| 14~17 | 89 67 45 33 | 值 | -33H 得 56 34 12 00 |
| 18 | 54 | CS | 字节 0~17 之和 0x154 的低 8 位 |
| 19 | 16 | 结束符 | 帧结束 |

CS 校验：`sum(前 18 字节) = 0x154 → 0x54`。

### 3.3 解码到读数输出

按标准解析顺序（去前导 → 校 CS → 认控制码 → -33H → 按 DI 语义转数值）：

```
1. 数据域 -33H           → DI 00 00 01 00 , 值 56 34 12 00
2. 传输序还原 DI3DI2DI1DI0 → 00 01 00 00  （当前正向有功总电能）
3. BCD 低字节在前还原      → 123456
4. 查 DI 元数据小数位=2、单位=kWh → 123456 / 100 = 1234.56 kWh
```

最终读数输出：

```
DI      : 00010000  (Forward active total energy / 当前正向有功总电能)
Value   : 1234.56 kWh
```

### 3.4 用仓库代码复现

```bash
# 生成标准读数据请求帧（输出与 3.1 完全一致）
moon run cmd/main -- --address 129078563412 read

# 解析标准应答帧（输出 control=0x91、DI 名称、逻辑数据域）
moon run cmd/main -- parse \
  "68 12 90 78 56 34 12 68 91 08 33 33 34 33 89 67 45 33 54 16"

# 完整闭环示例：构造请求 → 电表应答 → 解码 → 格式化 → 校验
moon run cmd/roundtrip
#   阶段 4 输出：1234.56 kWh

# 一键验证所有断言（含上述黄金报文的逐字节比对）
moon test
```

`commands_wbtest.mbt` 中的两条黄金用例分别锁定请求/应答帧的逐字节结果：
`golden: standard read request frame matches byte for byte` 与
`golden: standard read reply decodes to 1234.56 kWh`，确保文档与实现不会漂移。

## 4. 本次更正对照表

| 项目 | 更正前（不符合） | 更正后（符合 645-2007） |
|---|---|---|
| 长度字段 | 双字节小端 `L(2)`、帧长 13+L | **单字节 L**、帧长 12+L |
| 读数据控制码 | 0x01 | **0x11** |
| 读数据正常应答 | 0x81 | **0x91** |
| 读数据异常应答 | 0xC1 | **0xD1** |
| 异常判定 | 只看 D6 | **D7 与 D6 同时为 1** |
| 数据域编码 | 无 +33H | **发送 +33H / 接收 -33H** |
| 功能码表 | 0x01~0x0F 连续 | **08H、11H~1BH 离散定义** |
| 广播校时 | 0x05 | **0x08** |
| DI 定义 | 正向总电能 = 00000000 | **00010000**，传输序 DI0..DI3 |
| CS 计算范围 | 按双字节头计算 | **第一个 68H 至数据域末尾** |
